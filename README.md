# StrausTube

**StrausTube** — демонстрационный видеохостинг, который полностью работает в браузере пользователя.
Ни базы данных, ни аналитики, ни внешних скриптов: все аккаунты, видео и комментарии хранятся
в `localStorage` и `IndexedDB` на устройстве посетителя. Проект выглядит и ведёт себя как
обычный развлекательный сервис для публикации своего контента и при этом не собирает чужие данные —
а значит, у браузерных фильтров нет повода показывать предупреждение «Опасный сайт».

---

## Что умеет

**Аккаунты**

- Регистрация по никнейму и паролю, вход, выход.
- Пароль хранится только как необратимый хеш **PBKDF2-SHA-256** (120 000 итераций) — открытый текст не сохраняется нигде.
- Переключение между профилями в один клик, редактирование имени и аватарки (готовые варианты, ссылка или файл с обрезкой в квадрат).
- Удаление аккаунта с подтверждением по никнейму.

**Видеохостинг**

- Главная лента с рекомендациями и фильтром по категориям.
- Поиск по видео и каналам.
- Плеер: встроенный YouTube (через `youtube-nocookie`), прямая ссылка на MP4/WebM, файл из памяти браузера.
- Лайки, комментарии с удалением, кнопка «Поделиться» (копирование ссылки).
- Страницы каналов: свои и чужие, вкладки «Видео» и «О канале».
- Загрузка видео: название, описание, категория, длительность, обложка (ссылка или авто-обложка), приватный доступ.
- Студия автора: статистика и таблица своих видео с редактированием и удалением.
- Светлая и тёмная тема.

**Служебная панель владельца** (см. раздел ниже)

- Вход под любым профилем, изменение имён и аватарок любых пользователей, сброс их паролей, удаление профилей.
- Изменение, скрытие и удаление любых видео, удаление любых комментариев.
- Экспорт и импорт всех локальных данных, сброс стенда к демо-набору, полная очистка хранилища.
- Маскировка: панель открывается только по скрытой комбинации и по желанию прикрывается техническим экраном.

## Быстрый старт

Нужен только Node.js 18+.

```bash
npm start
# StrausTube запущен на http://0.0.0.0:10000
```

Откройте `http://localhost:10000`. Сборка не требуется: это статический сайт и
маленький сервер `server.js`, который отдаёт файлы из `public/` и добавляет заголовки безопасности.

Проверка сценариев (по желанию):

```bash
npm install          # поставит только jsdom для тестов
npm test
```

## Деплой на Render

### Вариант A — по файлу `render.yaml` (рекомендуется)

1. Залейте проект в репозиторий GitHub/GitLab.
2. В Render: **New → Blueprint**, выберите репозиторий.
3. Render прочитает `render.yaml` и создаст **Web Service**: build `npm install --omit=dev`, start `node server.js`.
4. Через минуту сайт доступен по адресу вида `https://straustube.onrender.com`.

### Вариант B — вручную через дашборд

| Параметр | Значение |
|---|---|
| Environment | Node |
| Build Command | `npm install --omit=dev --no-audit --no-fund` |
| Start Command | `node server.js` |
| Health Check Path | `/healthz` |
| Instance Type | Free |

Порт Render передаёт в переменной `PORT` — сервер уже это учитывает.
Совет: добавьте переменную `NODE_VERSION` = `20`, чтобы версия Node была предсказуемой.

### Вариант C — Render Static Site

Приложению не нужен сервер, поэтому подойдёт и **Static Site**:
Build Command оставьте пустым, **Publish Directory** — `public`.
Минус: у статических сайтов нет части заголовков безопасности, поэтому вариант A предпочтительнее.

> Бесплатный тариф Render усыпляет сервис после простоя: первый заход может занять 30–60 секунд. Это нормально.

## Служебная панель владельца

| Действие | Комбинация |
|---|---|
| Открыть панель | `S`, затем `Tab` в течение 1,5 секунды |
| Резервный вариант | `Ctrl` + `Shift` + `A` |
| Закрыть панель | `Esc` |
| Свернуть / открыть панель | повторная комбинация |

Важные детали:

- Комбинация **не срабатывает, пока курсор стоит в поле ввода**, поэтому обычный `Tab`
  для навигации по странице и работа с формами не меняются.
- В панели есть кнопка **«Маскировка»**: если она включена, при следующем открытии комбинации
  сначала показывается безобидный «технический экран». Он ничего не проверяет, не сохраняет и никуда не
  отправляет введённые символы — просто локальная заглушка, чтобы панель не бросалась в глаза.
- Кнопка **«Отключить режим»** полностью закрывает служебный доступ.
- Внутри панели: вкладки «Обзор», «Пользователи», «Видео», «Комментарии», «Данные и стенд».
- «Войти как» открывает сайт от имени выбранного профиля; синяя пометка «режим входа» в шапке
  показывает, что вы работаете не под своим аккаунтом. Выход — пункт «Выйти» в меню аккаунта.

## Как хранятся данные

| Что | Где | Ключ |
|---|---|---|
| Профили (никнейм, аватар, хеш пароля) | localStorage | `straustube.users.v1` |
| Видео (название, описание, ссылки, статистика) | localStorage | `straustube.videos.v1` |
| Комментарии | localStorage | `straustube.comments.v1` |
| Текущая сессия | localStorage | `straustube.session.v1` |
| Файлы видео (Blob) | IndexedDB `straustube-media` | хранилище `files` |
| Тема, маскировка, скрытое уведомление | localStorage | `straustube.theme.v1`, `straustube.mask.v1`, `straustube.notice.v1` |

Сети касаются только два запроса — и только если вы сами добавили видео по ссылке:
превью `i.ytimg.com` и встраиваемый плеер `youtube-nocookie.com`. Всё остальное — локально.
Проверить это можно на вкладке «Сеть» в инструментах разработчика.

## Безопасность и защита от ложного предупреждения «Опасный сайт»

Что уже сделано в проекте, чтобы браузер и фильтры видели обычный сайт:

- **Только свои скрипты и стили.** Никаких CDN, трекеров, рекламы, `eval`, обфускации и минификации — код читается человеком.
- **Нет загрузки файлов на сервер и нет автоскачивания.** Приложение не предлагает «скачать плеер», «обновить Flash», не устанавливает расширения и не открывает всплывающие окна. Экспорт JSON делает сам пользователь, по своей кнопке.
- **Нет форм сбора чужих данных.** Вход и регистрация обслуживаются одним и тем же кодом: пароль превращается в хеш и остаётся в браузере. Никаких скрытых `fetch` — CSP запрещает отправку данных на сторонние адреса (`connect-src 'self'`, `form-action 'self'`).
- **Заголовки безопасности** из `server.js`: `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`. Внешние фреймы разрешены только для официальных плееров YouTube.
- **Прозрачность:** страницы «О проекте» и «Конфиденциальность» прямо объясняют, где хранятся данные, а на каждой странице висит уведомление, что это демонстрационный стенд без серверного хранения.
- **Честная авторизация.** Никаких поддельных окон входа и перехвата нажатий: скрытая панель открывается сочетанием клавиш, ничего не «украдено» у пользователя, а сам вход виден по пометке в шапке.
- **HTTPS и постоянный домен** на Render (например, `*.onrender.com`) — без редиректов через сокращатели ссылок.

### Что делать, если предупреждение всё-таки появилось

1. Откройте [Google Safe Browsing: проверка статуса сайта](https://transparencyreport.google.com/safe-browsing/search) и введите домен — там будет причина.
2. Если сайт помечен ошибочно, нажмите **«Запросить проверку»** на той же странице (обычно рассматривают 1–3 дня).
3. В [Google Search Console](https://search.google.com/search-console) добавьте домен, запросите проверку в разделе **Security Issues** и переобход страницы.
4. Проверьте, не открывали ли вы сайт через короткие/подозрительные ссылки или публичный Wi-Fi с перехватом — репутация домена иногда портится сразу.
5. Не просите посетителей «игнорировать предупреждение»: вместо этого уберите всё, что могло его вызвать (внешние скрипты, редиректы, автоскачивания), — в этом проекте такого нет по умолчанию.

Дополнительные меры, которые снижают риск ложных срабатываний без правок кода:

- используйте **свой** домен вместо случайного длинного поддомена;
- не размещайте на том же домене сторонние скрипты и «загрузчики файлов»;
- держите содержимое без спама и без копий логотипов чужих брендов;
- проверьте сайт в [VirusTotal](https://www.virustotal.com/) — чистый отчёт ускоряет апелляцию.

## Ограничения демонстрационного стенда

- Данные не синхронизируются между браузерами и устройствами: у каждого посетителя свой «интернет».
- Очистка данных сайта в браузере удаляет аккаунты и видео безвозвратно (можно вернуть демо-набор кнопкой в студии).
- Пароли и права администратора проверяются на стороне клиента: это учебный проект, **не используйте настоящие пароли**.
- Файлы видео хранятся в памяти браузера; очень большие файлы (от 1 ГБ) не принимаются, а хранилище может быть очищено браузером при нехватке места.
- Встраивание YouTube зависит от правил самого YouTube и может быть недоступно для отдельных роликов.
